## Why

Linux, macOS and Windows built and ran the same ~1200 quick tests on every push. They all test the same platform independent code. Most of them check decoders and DSP: the same C++ on every OS. Running them three times adds runner time, but only once tells you something.

| Job (last CI run) | Build | Quick tests | Total |
|---|---|---|---|
| Windows x64 | 138 min | 98 min | 4 h 04 |
| Linux x86_64 | 83 min | 75 min | 2 h 44 |
| macOS arm64 | 59 min | 54 min | 1 h 58 |

With this PR, **Windows runs every quick test**. **Linux and macOS build and run only the tests whose code differs per OS.**

Reason: Windows is used by most of the users. And as far as I know, are the developers not using windows. So I have chosen to run all platform independent tests on windows.

## What changes

- **`tools/platform_tests.py` → `tests/platform_tests.txt`**: the generated list of tests whose code differs per OS, one line per test with its build target and the reason:
  - `platform` (217): tests in OS-facing areas (`source`, `net`, `server`, `audio`, `codec`, `plugin`, `session`, `engine`, …), every `timing` test, and tests whose own source has `#ifdef _WIN32`/`__APPLE__`, sockets, `dlopen`/`LoadLibrary`, processes, text-mode `fopen`, data paths, local time, audio devices or GUI code. Also `memory_recall_app`, which is only registered on macOS/Windows.
  - `kernels` (34): SIMD/FFT/FEC kernels (`tests/dsp`, `tests/fec`, `tests/t2`, viterbi/ldpc/fft/resampler tests).
- **`CMakeLists.txt`**: reads the list into the test labels. New cache variable `DECT2_TESTS_ONLY` (default empty = every test) takes the same pattern as `ctest -L`, e.g. `platform` or `platform|kernels`. Only those tests' programs stay in `all`. The core, app and tools always build.
- **`ci.yml`** (push):

  | Job | `DECT2_TESTS_ONLY` / `ctest -L` | Why |
  |---|---|---|
  | Windows x64 | *(unchanged: every test)* | the reference run for the shared C++ |
  | Linux x86_64 | `platform` | same x86-64 kernels as Windows, so only the OS-facing tests |
  | macOS arm64 | `platform\|kernels` | the only arm64 run on push: NEON, Accelerate, Metal |

  The timing step is unchanged (all 38 timing tests are `platform`). The OpenGL 3.1 software run on Linux is unchanged (the app still builds).
- **`ci-full.yml`** (nightly / manual): new `macOS arm64 (quick tier)` job (`ctest -LE slow`). It runs the decoders as Clang builds them on arm64 once a day, since on push they only run as GCC builds them on x86-64 (Windows). It's a separate job because the slow tier alone already fills the 6 h job limit.
- **`CONTRIBUTING.md`**: when and how to regenerate the list.

## Expected effect

Replaying the per-test times of the last CI run (`ctest-fast.log` artifacts) against the new selection:

| | Tests per push | Share of quick-test time | Test step (est.) |
|---|---|---|---|
| Linux x86_64 | 178 / 1198 | 11% | ~75 → ~10 min |
| macOS arm64 | 213 / 1199 | 27% | ~54 → ~15 min |
| Windows x64 | all | 100% | unchanged (~98 min) |

Linux and macOS also skip compiling 1130 and 1096 test programs. That saving is still to be measured.

**Wall time per push stays about 4 h**, because Windows, which runs everything, was already the longest job. The gain is runner time on Linux and macOS, plus faster feedback on OS-specific failures there.

## Trade-off

- **Linux:** the shared C++ is no longer run as Linux GCC/glibc builds it on push, but MinGW GCC on x86-64 is close. Linux-only behaviour (paths, sockets, audio, `__linux__` code) is in `platform`.
- **macOS:** arm64/Clang issues in decoders that aren't kernels (e.g. thresholds like the Apple-arm64 case in `test_hfdl_weak`) now show up in the nightly quick tier instead of on the push. NEON/Accelerate kernels still run on every push.
- **Compile errors:** a compile error in a test file that isn't listed only shows up in the Windows push build (still every test) or nightly. Core, app and tools compile on every OS on every push.

## Maintenance

The list is not automatic. After adding a test that touches the OS, regenerate it from a configured build directory (no build needed):

```
python3 tools/platform_tests.py build > tests/platform_tests.txt
```
